# Module memory: MCP

> Last reviewed: 2026-10-27.

## What it is
Laravel MCP server exposing Plamx module tools to external AI clients over `/mcp/plamx` and local STDIO.
Tools live in `app/Mcp/Tools`, registration in `app/Mcp/Servers/PlamxServer.php`.

## Confirmed rules
- The HTTP MCP route has no auth middleware; it only initializes the tenant via `routes/ai.php` and `InitializeTenancyByDomainOrSubdomain`. Tools that must work from ChatGPT therefore must not require authentication.
- Meeting tools are anonymous and tenant-guarded (`app/Mcp/Tools/Meetings/MeetingTool.php`). KPI tools follow the same public-read model and require only an initialized tenant (`app/Mcp/Tools/Kpis/Concerns/EnsuresKpiContext.php`).
- KPI data/analysis reads go through `KpisService` and `KpiRepository`. The hierarchy tree read reuses the existing report endpoint through `ModuleRouteDispatcher` (`reports/kpis/kpi-hierarchy-tree/data`) so web and MCP share one implementation; that controller action has no explicit authorization, and the MCP route only requires tenant initialization.
- `list-kpis-tool` filters by plan (`operational_plan_id`/`strategic_plan_id`/`without_relation`), relation type (`type`), owner (`owner_id`/`owner_ids`), search, and roots. `get-kpi-tool` returns one KPI with the same eager-loaded relations as `KpisController@show`.
- KPI plan filters must pass explicit `operational_plan_id='all_plans'`, `strategic_plan_id=null`, and `section_id=null` to avoid inheriting web-session plan/section filters (`KpiRepository::all`).
- KPI MCP output keeps owner and responsibles separate (`owner` + `responsibles`) and uses a shared formatter (`FormatsKpi`). Values are exposed as `initial_value`, `target_value`, `current_value` (= `progress`), and `verification_ratio` (= `verification_value`); raw `progress`/`verification_value` are also returned. The duplicate `achievement` attribute is hidden from MCP output. `get-kpi-tool` adds a `summary` block with the same separation plus `sub_kpis_count` (dynamic KPI children = مؤشرات فرعية) and `parent_kpis_count` (KPIs computed from this KPI) so ChatGPT can answer "has this KPI sub-KPIs?" without calling the dynamic-relations tool.
- Per-KPI analysis tools:
  - `list-kpi-measurement-points-for-kpi-tool` (the KPI-module name; the existing task tool already owns `list-kpi-measurement-points-tool`) lists measurement points with `kpi_id`, optional `from`/`to`, and `page`/`per_page`.
  - `list-kpi-executions-tool` lists executions newest-first with the responsible member and optional `KpiAnalysis` (`what_happened`, `how_it_happened`).
  - `compare-kpi-measurement-execution-tool` builds periods from `measurement_cycle` (default monthly) and returns `target_value`, `effective_target` (annual-target fallback), `actual_value`, `deviation`, `performance`, `has_measurement`, and `has_execution` per period. It mirrors `resources/js/kpisApp/components/details/overview.vue` (cumulative/percentage/average handling, non-cumulative deltas, polarity, annual-target fallback).
  - `get-kpi-gap-analysis-tool` returns `gap_value`/`base_gap`, `current_gap`, `remaining_gap`, `gap_progress`, `gap_progress_ratio`, `remaining_gap_ratio`, and `acceptable_deviation`; `include_periods=true` appends comparison rows.
  - `get-kpi-dynamic-relations-tool` returns the KPI's `dynamicRelations` rows with `relative_weight`, `verification_ratio`, and `impact_ratio = verification_ratio * relative_weight / 100`. KPI relations use `verification_value`; other relation types use `progress`. `parent_relations` exposes incoming `reverseDynamicRelations`, and `summary` returns total weight/impact. **This is the tool for "مؤشرات فرعية مرتبطة" (linked sub-KPIs)**: a dynamic/partially-dynamic KPI is computed from the KPIs/projects/tasks in its dynamic relations. The separate `leading_kpis`/`lagging_kpis` relation (`kpi_performance_relations`, `performance_kpi_type` leading/lagging) is a different performance model, NOT sub-KPIs — descriptions and server instructions explicitly tell ChatGPT not to confuse them.
  - `get-kpi-hierarchy-tree-tool` accepts `strategic_plan_id` or `strategic_plan_name`, optional `level_id` (`all` default, `strategic_N`, `operational_N`, `project`, `task`), and reuses `KpiHierarchyController@getData`. With no plan it returns `requires_strategic_plan` and available plans; ambiguous names return matching plans. KPI nodes expose `progress` as the absolute current value and `achievement` as Effectiveness / الفاعلية.
- The analysis reads use `KpiRepository::findBasic()` (accessible KPI without eager-loading the full detail graph). List tools use `paginateMeasurementPoints()`/`paginateExecutions()`; comparison uses `measurementPoints()`/`executions()` without execution relations. The dynamic-relations tool uses `KpiRepository::find()` because it needs `dynamicRelations.relationable` and `reverseDynamicRelations.kpi`.
- Report-level KPI tools (2026-10-27, phase 1 of the "make all 13 KPI reports AI-usable" task): `get-kpi-portfolio-summary-tool`, `get-kpi-performance-table-tool`, and `get-kpi-insights-tool`. All share `ResolvesKpiReportScope` concern (scope may be unscoped = whole tenant, unlike the hierarchy tool) and `KpiReportInsightsService` (flat `app/Services`): `reportScope()` mirrors `KpisReportController::kpisFilter` (4-case plan filter WITHOUT `orWhereNull`, `relation_type` with `StrategicStructureLevel_N`/`OperationalStructureLevel_N` parsing, `owner_id`, `section_id` via owner `current_section_id`, name/code `search`), `resolvePeriod()` (enum periods + `from_date`/`to_date` pair; never both period and dates), `periodPerformance()` (same polarity formula as `getKpisReportsData`, optional `deviation_value` cap at `100 + deviation`), weighted effectiveness `sum(verification*weight)/sum(weight)` over weight>0, `impact_ratio = verification*weight/100`, and true-percentage weighted period achievement using `period target / annual target` ratios. Every response carries `context`, `headline`, `definitions`, `suggested_questions`, `sources` (static report names, no URLs — unauthenticated context).
- Tool naming follows the `-tool` kebab convention; the three report tools are registered right after `get-kpi-hierarchy-tree-tool` in `PlamxServer::$tools`. Phase 2 tools (`get-kpi-owner-scorecard`, `get-kpi-forecast`, `get-kpi-data-quality`, `explain-kpi-performance`) are planned but not built.

## Fixes applied
- 2026-10-26: Added KPI MCP read tools and explicit repository filters; fixed the `without_relation` branch calling the non-existent `operational_plan()` relation to `operationalPlan()`. Tests: `tests/Feature/Mcp/KpiToolsTest.php`.
- 2026-10-26: KPI list/get now separate owner from responsibles and label `current_value` vs `verification_ratio` alongside initial/target values.
- 2026-10-26: Added per-KPI measurement points, executions, measurement-vs-execution comparison, and gap analysis MCP tools. Exposed `KpiExecution` analysis and responsible member data. Tests: `tests/Feature/Mcp/KpiToolsTest.php` (13 tests, 163 assertions) and the full MCP suite (34 tests, 425 assertions).
- 2026-10-26: Added `get-kpi-dynamic-relations-tool` (partial/dynamic relation weights, verification, impact, parent relations) and `get-kpi-hierarchy-tree-tool` (strategic-plan-filtered hierarchy). Tests: `KpiToolsTest` 15 tests / 217 assertions; full MCP suite 36 tests / 479 assertions.
- 2026-10-27: Added the three report-level KPI tools (portfolio summary, performance table with period target/actual, insights) built on `KpiReportInsightsService` + `ResolvesKpiReportScope`. Fixed audited controller bugs in the new code only (weighted % normalization, signed per-polarity deviation); the web `KpisReportController` was not modified. Tests: `KpiToolsTest` 23 tests / 340 assertions; full MCP suite 44 passed / 602 assertions.
- 2026-10-27: Clarified the "مؤشرات فرعية مرتبطة" (linked sub-KPIs) intent for ChatGPT: it means the KPIs/projects/tasks in a dynamic/partially-dynamic KPI's `dynamicRelations` — answered by `get-kpi-dynamic-relations-tool`, NOT the leading/lagging KPIs. Extended the dynamic-relations + get-kpi tool descriptions and server instructions to say so explicitly, and added `sub_kpis_count`/`parent_kpis_count` to the `get-kpi-tool` summary. Tests: `KpiToolsTest` 23 tests / 343 assertions.
